## 一、项目概述

### 1.1 项目定位

**AI 对话评测系统 Pro** 是一个基于 LLM-as-a-Judge 的全链路 AI 质量评测平台，专注于：

- 🎯 **多模式评测**：覆盖单轮对话、多轮对话及 Agent 智能体任务
- 🔍 **全链路追踪**：引入 Trace 机制，记录输入输出、性能指标与决策链
- 📊 **可观测性分析**：通过多维图表发现质量瓶颈与性能异常

### 1.2 核心价值

| 维度 | 价值 |
|------|------|
| **效率** | 统一调度 + 合并评测，评测效率大幅提升 |
| **精准** | 最低分惩罚机制，不遗漏严重问题 |
| **深度** | Agent 评测支持工具调用链 (Tool Calls) 与思维链 (Chain of Thought) 分析 |
| **闭环** | 评测结果持久化存储，支持长期趋势追踪 |

## 二、功能介绍

### 2.1 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                     Streamlit 前端 (UI)                      │
│     [Dashboard] [Eval Center] [Data Explorer] [Settings]     │
├──────────────────────────────────────────────────────────────┤
│                统一评测调度器 (eval_dispatcher)              │
│            ↙                                      ↘          │
│  ┌─────────────────┐                      ┌────────────────┐ │
│  │ run_eval.py     │                      │ agent_eval.py  │ │
│  │ (对话评测引擎)   │                      │ (Agent 引擎)   │ │
│  └─────────────────┘                      └────────────────┘ │
├──────────────────────────────────────────────────────────────┤
│               TraceStore (SQLite traces.db)                  │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 功能模块详解

#### 📊 首页看板 (Dashboard 2.0)
- **组合趋势图 (Combo Chart)**: 同时展示评测数量(柱状)与平均分趋势(折线)，直观反映质量波动。
- **性能散点图 (Scatter Plot)**: 分析 Latency(X轴) 与 Score(Y轴) 的关系，快速发现"慢且差"的异常点。
- **能力热力图 (Heatmap)**: 展示不同评测模式(Agent/Chat)在各评分维度上的强弱分布。

#### 🚀 评测中心 (Eval Center)
- **统一入口**: 无论是上传 CSV/JSON 还是加载测试数据，均通过统一入口处理。
- **智能识别**: 仅需上传数据，系统自动识别是单轮、多轮还是 Agent 数据。
- **实时反馈**: 详细的进度条与状态展示 (成功/跳过/错误)。
- **结果摘要**: 评测完成后即刻展示摘要卡片，包含总数、平均分和状态分布。

#### 📜 数据浏览 (Data Explorer)
- **Trace 列表**: 仿 Langfuse 风格的富列表，展示时间、ID、预览、分数(彩色进度条)、耗时与 Token。
- **深度详情页**:
  - **Chat**: 气泡式对话还原，点击气泡查看该轮次的 6 维度评分。
  - **Agent**: 时间轴展示工具调用链，透视 Agent 的思考过程与决策逻辑。

#### ⚙️ 系统设置
- **评分标准**: 在线编辑 `rubric.json`，即时调整评分维度与权重。
- **Prompt 工坊**: 集成 Prompt 优化工具，辅助进行 Prompt 工程迭代。

## 三、评测思路

### 3.1 评测范式：LLM-as-a-Judge

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  输入数据 (IO)  │ + │  评分标准       │ → │  LLM 评测裁判  │
│  (Chat/Agent)   │    │  (rubric.json)   │    │  (打分+分析)    │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### 3.2 统一调度设计 (v0.9.0)

引入 `eval_dispatcher` 解决以往评测入口分散、逻辑重复的问题：

1. **输入标准化**: 将杂乱的输入 (user_turns, messages, agent task) 统一转换为标准格式。
2. **自动路由**:
   - `eval_type='agent'` -> `agent_eval.py`
   - `eval_type='multi_turn'` -> `run_eval.py`
3. **结构化输出**: 所有引擎统一返回 `EvalResultDTO`，包含分数、TraceID、耗时等标准化字段。

### 3.3 综合分算法

```python
综合分 = min(平均分, 最低分 + 1.5)
```

**设计原理**：
- 单纯平均分会掩盖某维度的严重问题。
- 最低分惩罚确保重大缺陷（如幻觉、安全问题）能拉低整体分数，触发警报。

## 四、评测指标

### 4.1 对话评分体系 (6 维度)

| 维度代码 | 中文名称 | 评估重点 |
|----------|----------|----------|
| `clarity` | 表达清晰度 | 语句通顺、逻辑连贯 |
| `proactivity` | 主动引导 | 需求挖掘、对话推进 |
| `content` | 内容价值 | 信息量、利益点突出 |
| `authority` | 专业权威 | 术语准确、信任建立 |
| `accuracy` | 信息准确 | 事实正确、无虚假承诺 |
| `empathy` | 语气共情 | 亲和力、换位思考 |

### 4.2 Agent 评分体系 (4 维度)

| 维度代码 | 中文名称 | 评估重点 |
|----------|----------|----------|
| `task` | 任务完成 | 目标达成情况 |
| `tool` | 工具使用 | 参数正确性、工具选择 |
| `reasoning` | 推理逻辑 | Thought 过程合理性 |
| `efficiency` | 执行效率 | 步骤冗余度 |

## 五、数据格式要求

### 5.1 统一数据结构

推荐使用包含 `eval_type` 的标准 JSON 格式：

```json
[
  {
    "session_id": "agent_test_01",
    "eval_type": "agent",
    "task": "查询库存",
    "tool_calls": [...],
    "output": "库存充足"
  },
  {
    "session_id": "chat_test_01",
    "eval_type": "multi_turn",
    "messages": [...]
  }
]
```

### 5.2 数据库表结构 (SQLite)

核心表 `traces` 存储所有评测记录：

```sql
CREATE TABLE traces (
    trace_id TEXT PRIMARY KEY,
    session_id TEXT,
    eval_type TEXT,
    input_data TEXT,
    output_data TEXT,
    model TEXT,
    latency_ms INTEGER,
    token_usage TEXT,    -- JSON {"total": 100, ...}
    avg_score REAL,
    status TEXT,
    created_at TIMESTAMP
);
```
